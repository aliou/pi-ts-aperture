Add manual Pi-to-Aperture provider mapping for proxy mode, so non-admin grants can use the extension end-to-end.

Non-admin Aperture grants get 403 on the admin-only `/aperture/config` and therefore lose automatic base-URL matching — they could only proxy a provider when its Pi provider id happened to equal an Aperture gateway provider id. Manual mapping closes that gap.

- Config: `proxy.upstreamProviders[]` gains an optional `apertureProviderId` (the Aperture gateway provider id). `id` stays the Pi provider id (routing key); `apertureProviderId` defaults to `id`, so existing configs keep working. Routing never uses `apertureProviderId` — Aperture routes by the model id in the request body, and proxy registration only overrides `baseUrl`/`apiKey`/headers on the existing Pi provider.
- `mapProxyProviders` now MERGES automatic matches with persisted (manual) entries, so manual mappings survive a settings submenu reopen instead of being clobbered by the rebuilt auto-match list. Manual entries whose local Pi provider has disappeared are kept but flagged stale, not silently deleted. A persisted `apertureProviderId` override is honored on auto-matched providers too.
- `checkMissingModels` now looks models up under the mapped `apertureProviderId` (defaulting to `id`) instead of assuming Pi provider id == gateway provider id, so the gateway model check works for manual mappings; the warning labels the mapping as `piId -> apertureId` when they differ.
- A `004` migration backfills `apertureProviderId = id` on existing entries (disk normalization). The loader's `afterMerge` (`normalizeProxiedProviders`) is the runtime safety net that fills `apertureProviderId ?? id` and `shouldCheckGatewayModels ?? true`, so the resolved `Required` shape holds even for hand-edited or partially-written configs (this also fixes a latent gap where `shouldCheckGatewayModels` was not normalized).
- Settings Proxy submenu: replaced the generic boolean list with a custom `ProxyUpstreamProvidersEditor` that lists EVERY local Pi provider as a row (including `anthropic` / `openai-codex` when they did not auto-match, so they are visible and configurable), shows auto-matched and manual mappings with `[auto]`/`[manual]` origin tags, and reuses `FilterableChecklist` (search input + list) for both the provider list and the Aperture target picker so the user can type to filter long lists. Actions use keys that never collide with typing: `Space` set/change the Aperture target (opens the picker; for an unmapped row this also enables it), `Ctrl+G` toggle the gateway model check for the highlighted row, `Esc` back. Clearing a mapping is done by picking the `— Clear mapping —` row in the picker. An auto-matched provider (e.g. `anthropic`) can be re-pointed at a different Aperture gateway endpoint, and a provider with no auto-match can still be mapped. Non-admin empty state points users to manual mapping.
- Onboarding: the proxy step now embeds the same `ProxyUpstreamProvidersEditor`, so manual Pi-to-Aperture mapping is available during onboarding too. The wizard intercepts Esc (cancel) before steps, so onboarding uses `Enter` to continue (list mode) / back out of the picker, while settings uses `Esc`. `FilterableChecklist.onCtrlG` now receives the highlighted item id so per-row gateway-check toggle works from a searchable list. A persisted `apertureProviderId` is carried through onboarding state/result types so a re-onboard does not drop existing manual mappings.

Admin users keep the richer base-URL matching with no regression.
